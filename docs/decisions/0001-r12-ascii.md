# ADR 0001 — DXF R12 ASCII as the initial format

Date: 2026-11-01

Status: accepted

## Context

The library must read and write DXF files for structural use. DXF exists in many
versions with substantial differences: available entities, handle requirements,
present sections and text encoding.

The alternatives were:

1. DXF R12 ASCII (`AC1009`).
2. DXF 2000 ASCII (`AC1015`).
3. Both versions from the start.

## Decision

The first release supports **DXF R12 ASCII only**.

Rationale:

- R12 is readable by virtually every CAD application.
- The structure is simpler: `HEADER`, `TABLES`, `BLOCKS`, `ENTITIES`, `EOF`.
- Handles are optional, so the writer does not need an object reference graph.
- The `CLASSES` and `OBJECTS` sections do not exist, so no object model is
  required.
- The limits are known and documentable: no `LWPOLYLINE`, `SPLINE`, `MTEXT`.

## Consequences

Positive:

- Verifiable, testable scope.
- Maximum interoperability on output.
- No third-party dependency required.

Negative:

- Polylines use `POLYLINE`/`VERTEX`/`SEQEND`, which is more verbose.
- No modern curved entities.
- Text is not UTF-8: code page handling remains partial.
- Moving to later versions will require additional work, not only new entities.

## Rejected alternatives

- **DXF 2000 immediately**: it would have required mandatory handles, object
  references and the `OBJECTS` section before having a stable R12 round-trip.
- **Both versions**: it would have doubled the test matrix without a confirmed
  use case.

## Verification

- `$ACADVER` is validated as `AC1009`.
- The entity matrix is the one in [dxf-r12.md](../dxf-r12.md).
- An R13 or later file produces `ErrUnsupportedVersion`.
