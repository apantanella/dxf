# Formato DXF R2013 scritto dalla libreria

Specifica tecnica del file DXF ASCII R2013 (`$ACADVER` = `AC1027`) che `Encode` scrive per `VersionR2013`, e in particolare del file vuoto prodotto da `NewDocumentVersion(VersionR2013)`.

## Fonte e grado di verifica

La struttura descritta qui è quella della variante `v00-baseline` dell'esperimento T1, generata da `t1/generate.py` (funzione `build` con tutte le opzioni attive). Quel file contiene, oltre alla struttura minima, tre entità: LINE, CIRCLE, TEXT.

Legenda usata nel documento:

- **Provato**: presente nei file T1 e aperto senza errori in ZWCAD 2023 e CadCraft 0.16.0 (2 novembre 2026).
- **Da verificare**: aggiunto da conoscenza del formato, non presente nei file T1 o non provato in un CAD. Va confermato con le fixture reali (T10) e con il G1 (T11).

Nessuna affermazione di questo documento riguarda AutoCAD, che non è stato provato.

## Forma del file

| Aspetto | File T1 (provato) | Note |
|---------|-------------------|------|
| Fine riga | CR LF | `tags.WithCRLF()` |
| Codice di gruppo | allineato a destra su 3 colonne | `tags.WithPaddedCodes()` |
| Codifica | UTF-8 | ADR 0004 |
| Reali | formato Python: `0.0`, `100.0`, `1.34`, `1e+20`, `-1e+20` | il writer Go attuale scrive `0.0` per lo zero e il formato `'f'` per gli altri valori (`1e20` diventa `100000000000000000000`): forma non provata nei CAD, da verificare in G1 |
| Ordine delle sezioni | HEADER, CLASSES, TABLES, BLOCKS, ENTITIES, OBJECTS, poi `0 EOF` | |

Ogni sezione è `0 SECTION`, `2 <nome>`, contenuto, `0 ENDSEC`.

## Handle e owner

Nel file T1 gli handle sono assegnati in sequenza da `1` e `$HANDSEED` è il primo libero. La tabella seguente riporta gli handle di `v00` come esempio; la libreria non è tenuta a riprodurre questi valori, ma a rispettare le relazioni di owner.

| Handle | Oggetto | Owner (330) |
|--------|---------|-------------|
| 1 | DICTIONARY radice | 0 |
| 2 | DICTIONARY `ACAD_GROUP` | 1 |
| 3 | DICTIONARY `ACAD_LAYOUT` | 1 |
| 4 | ACDBDICTIONARYWDFLT `ACAD_PLOTSTYLENAME` | 1 |
| 5 | ACDBPLACEHOLDER `Normal` | 4 |
| 6–E | TABLE VPORT, LTYPE, LAYER, STYLE, VIEW, UCS, APPID, DIMSTYLE, BLOCK_RECORD | 0 |
| F | VPORT `*Active` | 6 |
| 10, 11, 12 | LTYPE `ByBlock`, `ByLayer`, `Continuous` | 7 |
| 13 | LAYER `0` | 8 |
| 14 | STYLE `Standard` | 9 |
| 15 | APPID `ACAD` | C |
| 16 | DIMSTYLE `Standard` (handle in `105`) | D |
| 17 | BLOCK_RECORD `*Model_Space` | E |
| 18 | BLOCK_RECORD `*Paper_Space` | E |
| 19, 1A | BLOCK / ENDBLK `*Model_Space` | 17 |
| 1B, 1C | BLOCK / ENDBLK `*Paper_Space` | 18 |
| 1D | LAYOUT `Model` | 3 |
| 1E | LAYOUT `Layout1` | 3 |
| 1F, 20, 21 | LINE, CIRCLE, TEXT | 17 |

`$HANDSEED` = `22`.

Regole:

- Ogni TABLE ha owner `0`; ogni record ha owner = handle della sua TABLE.
- BLOCK ed ENDBLK hanno owner = handle del BLOCK_RECORD del blocco.
- Ogni entità ha owner = handle del BLOCK_RECORD del blocco che la contiene (`*Model_Space` per la sezione ENTITIES). Per le entità dello spazio carta l'owner è `*Paper_Space` (da verificare: il file T1 non contiene entità in spazio carta).
- VERTEX, SEQEND e ATTRIB: owner = handle della POLYLINE o INSERT che li contiene (da verificare: non presenti nei file T1).
- Gli handle si scrivono in esadecimale maiuscolo senza zeri iniziali.

## HEADER

Ogni variabile è `9 $NOME` seguita dai suoi gruppi. Ordine di `v00`:

| Variabile | Gruppi | Valore in v00 | Note |
|-----------|--------|---------------|------|
| `$ACADVER` | `1` | `AC1027` | sempre |
| `$HANDSEED` | `5` | primo handle libero (`22`) | maggiore di ogni handle presente (ADR 0006) |
| `$DWGCODEPAGE` | `3` | `ANSI_1252` | sempre (ADR 0004) |
| `$INSBASE` | `10`, `20`, `30` | `0.0`, `0.0`, `0.0` | |
| `$EXTMIN` | `10`, `20`, `30` | `0.0`, `0.0`, `0.0` | in v00 valori fissi; la libreria li calcola dalle entità |
| `$EXTMAX` | `10`, `20`, `30` | `100.0`, `100.0`, `0.0` | idem |
| `$LIMMIN` | `10`, `20` | `0.0`, `0.0` | |
| `$LIMMAX` | `10`, `20` | `420.0`, `297.0` | |
| `$LTSCALE` | `40` | `1.0` | |
| `$TEXTSTYLE` | `7` | `Standard` | |
| `$CLAYER` | `8` | `0` | |
| `$INSUNITS` | `70` | `4` (millimetri) | |
| `$MEASUREMENT` | `70` | `1` (metrico) | |

Le variabili presenti nel documento e non elencate qui si scrivono dopo quelle della tabella, in ordine stabile (ADR 0005). `$ACADVER`, `$HANDSEED` e `$DWGCODEPAGE` sono sempre calcolate dal writer e non copiate dal documento.

## CLASSES

Un record per classe degli oggetti scritti in OBJECTS:

```
  0 CLASS
  1 <nome DXF>
  2 <nome C++>
  3 ObjectDBX Classes
 90 0
 91 0
280 0
281 0
```

| `1` | `2` | Quando |
|-----|-----|--------|
| `ACDBDICTIONARYWDFLT` | `AcDbDictionaryWithDefault` | se c'è `ACAD_PLOTSTYLENAME` |
| `ACDBPLACEHOLDER` | `AcDbPlaceHolder` | se c'è il segnaposto `Normal` |
| `LAYOUT` | `AcDbLayout` | se ci sono oggetti LAYOUT |

Valori `90` (flag di proxy), `91` (contatore di istanze), `280`, `281` = 0 come in v00. Il valore corretto di `90` e `91` per queste classi è da verificare; con 0 i due CAD aprono il file.

Le classi lette da un file si conservano e si riscrivono identiche (R9). Le classi generate si aggiungono solo se mancano.

## TABLES

Ordine delle tabelle: VPORT, LTYPE, LAYER, STYLE, VIEW, UCS, APPID, DIMSTYLE, BLOCK_RECORD.

Intestazione di tabella:

```
  0 TABLE
  2 <nome tabella>
  5 <handle tabella>
330 0
100 AcDbSymbolTable
 70 <numero di record>
```

Chiusura: `0 ENDTAB`.

Intestazione di record (tutti tranne DIMSTYLE):

```
  0 <tipo record>
  5 <handle>
330 <handle tabella>
100 AcDbSymbolTableRecord
100 <marcatore del tipo>
```

Tabelle vuote: solo intestazione con `70 0` e `ENDTAB`. I record letti da file si conservano (R7 non le tipizza).

### APPID

Marcatore `AcDbRegAppTableRecord`. Record `ACAD`: `2 ACAD`, `70 0`. Sempre presente (R8). Ogni applicazione usata in un `1001` deve avere il suo record APPID (da verificare sui file reali; oggi garantito da `EnsureAppID`).

### DIMSTYLE

Intestazione di tabella con due gruppi in più dopo `70`:

```
100 AcDbDimStyleTable
 71 <numero di record>
```

Il record usa `105` per l'handle al posto di `5`:

```
  0 DIMSTYLE
105 <handle>
330 <handle tabella DIMSTYLE>
100 AcDbSymbolTableRecord
100 AcDbDimStyleTableRecord
  2 Standard
 70 0
340 <handle dello STYLE Standard>
```

Il `340` è lo stile di testo delle quote. Le altre variabili di quota non sono scritte (F2).

### BLOCK_RECORD

Marcatore `AcDbBlockTableRecord`. Un record per ogni blocco, più `*Model_Space` e `*Paper_Space` sempre presenti (R6):

| Codice | Valore v00 | Significato |
|--------|-----------|-------------|
| 2 | `*Model_Space` / `*Paper_Space` | nome del blocco |
| 340 | handle del LAYOUT `Model` / `Layout1` | layout associato |
| 70 | 0 | unità di inserimento |
| 280 | 1 | esplodibile |
| 281 | 0 | scalabile |

Per i blocchi utente il `340` è `0` o assente (da verificare: il file T1 non contiene blocchi utente).

## BLOCKS

```
  0 BLOCK
  5 <handle>
330 <handle BLOCK_RECORD>
100 AcDbEntity
 67 1                (solo *Paper_Space)
  8 0
100 AcDbBlockBegin
  2 <nome>
 70 0
 10 0.0
 20 0.0
 30 0.0
  3 <nome>
  1                  (vuoto: percorso xref)
  0 ENDBLK
  5 <handle>
330 <handle BLOCK_RECORD>
100 AcDbEntity
 67 1                (solo *Paper_Space)
  8 0

## ENTITIES

### Intestazione comune

Ogni entità inizia così (v00, provato):

```
  0 <tipo>
  5 <handle>
330 <handle BLOCK_RECORD owner>
100 AcDbEntity
 67 1                (solo entità in spazio carta)
  8 <layer>
```

Dopo il layer, e prima del marcatore specifico, vanno i gruppi comuni opzionali già scritti dal writer R12: `6` linetype, `62` colore, `60` invisibile. Questa posizione è da verificare: le entità di v00 non li hanno. Lo spessore `39` appartiene alla sottoclasse specifica (da verificare).

Tag conservati di reattori e dizionari di estensione (`102 {ACAD_REACTORS`, `330`…, `102 }`; `102 {ACAD_XDICTIONARY`, `360`, `102 }`) si scrivono subito dopo `5` e prima di `330` owner (da verificare; ADR 0007). I dati estesi (`1001` e seguenti) vanno in fondo all'entità.

### Marcatori di sottoclasse

| Entità | Marcatori dopo `100 AcDbEntity` | Stato |
|--------|----------------------------------|-------|
| LINE | `AcDbLine` | provato |
| POINT | `AcDbPoint` | da verificare |
| CIRCLE | `AcDbCircle` | provato |
| ARC | `AcDbCircle`, poi `AcDbArc` prima degli angoli `50` e `51` | da verificare |
| TEXT | `AcDbText`, poi di nuovo `AcDbText` prima del `73` | provato (v00 scrive il secondo marcatore in fondo, senza `73`) |
| SOLID, TRACE | `AcDbTrace` | da verificare |
| 3DFACE | `AcDbFace` | da verificare |
| POLYLINE | `AcDb2dPolyline` oppure `AcDb3dPolyline` secondo i flag `70` | da verificare |
| VERTEX | `AcDbVertex`, poi `AcDb2dVertex` oppure `AcDb3dPolylineVertex` | da verificare |
| INSERT | `AcDbBlockReference` | da verificare |
| ATTRIB | `AcDbText`, poi `AcDbAttribute` | da verificare |
| SEQEND | nessuno oltre `AcDbEntity` | da verificare |

Senza i marcatori ZWCAD 2023 apre il file senza avvisi ma con il disegno vuoto (v06): un errore qui non produce alcun segnale, quindi ogni entità ha un test con il file atteso in `testdata` (R11).

### Disposizione dei gruppi per entità

Le tre entità di v00 (provato):

```

TEXT      ... 100 AcDbText    10 20 30 (punto)   40 (altezza)  1 (testo)

Per le altre entità la posizione dei gruppi rispetto ai marcatori è da verificare. Proposta, costruita sui gruppi che il writer R12 già scrive:

## Cosa resta fuori

LWPOLYLINE, MTEXT, HATCH, DIMENSION, LEADER, MLEADER, ATTDEF, ELLIPSE, SPLINE come entità interpretate, spessori di linea e colori RGB come API, viewport dei layout, sezioni THUMBNAILIMAGE e ACDSDATA: in F1 si conservano se presenti nei file letti, non si generano.
